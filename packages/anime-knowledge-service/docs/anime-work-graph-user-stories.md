# 动画作品聚合与活动关联：User Stories

状态：**提案，供产品审核；尚未实现**。配套技术要求见 [anime-work-graph-requirements.md](anime-work-graph-requirements.md)。

## 已确认的产品决定

- KitaCon 展示的是一部「动画作品」（Anime Work），而不是每一季各一张卡。该作品的 TV 各季、剧场版和 OVA 在活动页合成一张卡。
- 具体活动若指向第二季或某部剧场版，后台必须保留那个精确的 Bangumi subject，不能只留下聚合后的作品。
- Bangumi Archive JSON Lines 继续作为 Knowledge Service 的版本化原始数据；网站可编辑、可发布的作品资料与活动关联存到 KitaCon **现有** Neon，不新建数据库服务。
- KB 的制作人员／声优履历不是其参加某活动、或该活动介绍其所有作品的证据。

## P0：第一版必须有

### US-01：观众只看见一张作品卡

作为观众，我在一个漫展的「相关动画」里只想看到一张《某作品》卡，不想分别看到第一季、第二季、剧场版和 OVA 四张卡。

**验收**：同一已确认作品的四个 Bangumi 条目都被活动引用时，列表只显示一张卡；卡片可展开「涉及的具体版本」，不会重复统计为四部动画。

### US-02：精确版本不被聚合抹掉

作为编辑，我需要知道活动官方日程提到的是哪一季／哪部剧场版，以及是哪一页证明了它。

**验收**：作品卡、session 与关系详情均能追溯到 `bangumi:subject:<id>`、活动 `sourceDocumentId`、原文摘录和 KB 版本；「剧场版首映」不能变成笼统的「TV 新作首映」。

### US-03：审核自动分组

作为编辑，我希望系统根据 Bangumi 关系提出作品分组，但不会把同世界观、联动、漫画原作或名字相同的无关作品擅自合并。

**验收**：界面列出建议成员、关系路径和理由；我可以接受、移除、拆组或合组；我的决定在 Archive 下次更新后保持有效。

### US-04：活动只发布有证据的关联

作为编辑，我希望活动页面只展示得到活动来源支持的作品，而不是某位嘉宾或公司的完整作品履历。

**验收**：官方页面明确写出作品时可建立待审关联；只有「声优到场」或「制作公司有展位」时不能自动把其所有作品公开挂到活动。未确认的建议只在编辑后台出现。

### US-05：声优见面会的关系可解释

作为编辑，我希望看见「官方日程提到角色／作品 → KB 识别角色、声优与具体动画 → 聚合到作品卡」的证据链。

**验收**：有官方活动证据和角色—声优数据时可提出对应作品关联；缺少 `person-characters` 时明确显示「无法确认配音角色」，不靠模型补造事实。

### US-06：制作公司活动不泛滥关联

作为编辑，我希望系统区分「该公司制作过动画」与「本场活动宣传这部动画」。

**验收**：仅凭公司名称和制作履历不自动生成公开作品卡；活动来源点名作品或具体 session 时，可以提出带制作职位和来源的关联。

### US-07：作品页面有可维护的资料

作为观众，我打开作品页能看到统一的标题、别名、简介、封面、版本、制作公司、主要角色／声优与相关活动。

**验收**：每个展示字段有来源和更新时间；缺失字段不由 LLM 编造；封面只使用符合公开展示权限的图片；人工锁定的标题、简介、图片不被下次 KB 导入覆盖。

### US-08：旧活动数据不丢失

作为运营者，我希望以前按 Bangumi subject 建立的候选和活动关系，升级后仍能查看与编辑。

**验收**：旧 `event.related_subject` 记录原样保留；新作品映射可以回填且可回滚；尚未匹配到作品的条目仍按原样显示，不会消失。

## P1：紧接着扩展

### US-09：名字相同也不误合并

作为编辑，我希望同名、翻拍、衍生、跨媒体原作、联动等模糊关系进入人工审核，而不是被「同名」或图连通自动合并。

**验收**：系统能解释未合并原因；允许编辑明确建立「衍生／改编／联动」关系，而不强制它们共用一张作品卡。

### US-10：新 KB 版本可以安全上线

作为运营者，我希望先看新 Archive 与现有作品的差异，再决定是否接受改变分组或字段的建议。

**验收**：导入成功不会直接改变已发布作品 ID 或人工修订；提供新增、移除、改名、关系变化清单；可回到旧快照。

### US-11：人工选择与搜索

作为编辑，我希望在 Event/Candidate 编辑页搜索一部动画或具体版本，手工关联、解除或更正。

**验收**：搜索结果同时显示作品和成员版本；选择作品不会丢失所选精确 subject；保存有审计记录，并可与自动建议区分。

## P2：后续场景，不阻塞第一版

- 一个活动同时涉及多部作品的跨界声优座谈／公司发布会。
- 角色名出现但作品名未出现的歧义解析。
- 新动画尚未进入 Bangumi Archive：允许先创建 KitaCon 作品，日后补外部 ID。
- 游戏、漫画、音乐与动画的跨媒体关系；相关但不默认合并为「同一部动画」。
- 粉丝关注作品后收到相关活动通知，但不得把 KB 的职业关系直接当活动公告。

## 请审核的边界规则

1. **默认合并**：已确认属于同一动画作品的 TV 季、剧场版、OVA；成员仍保留各自 ID。
2. **默认不合并**：漫画／游戏原作、同世界观、联动、只有共同角色的作品、独立衍生作；可由编辑明确调整。
3. **默认不公开**：仅由嘉宾／公司履历推出来的活动—动画关系。
4. **公开门槛**：活动来源明确提到作品；或者提到明确角色／具体版本且 KB 路径无歧义，并经编辑确认。任何情况下都保留活动来源证据。
